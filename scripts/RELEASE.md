# 双语发行日志门禁

候选构建仍使用 `pnpm app:build`。正式发行准备使用以下顺序；脚本不提交、不打标签、不启动 App，也不修改版本配置。

1. `pnpm release:check`：只读检查两份日志的未发布节都有内容，且历史版本序列逐项一致。任一条件不满足时退出码为 1。
2. `pnpm release:prepare --version 0.1.1 --date 2026-10-21`：预检指定的新版本和日期，仍不写文件。将示例版本和日期换成本次实际值。
3. 在全部验收通过、准备冻结发行内容后，用相同命令加 `--write`。它先运行相同硬门禁，再将两份未发布内容轮转为新版本，保留历史及顶部空的未发布节。拒绝重复版本；校验失败时两份文件都不改变。
4. 同步项目版本配置，使用既有 `pnpm app:build` 构建。核对冻结源码、包内技能、产物哈希和验收证据后，按仓库规则精确提交及打发行标签。

门禁运行在轮转前。轮转后为空的未发布节代表本次内容已经归档，不应为构建补写虚假的未来变化；下一次发行必须先积累新的双语未发布条目。脚本通过不代表产品已验收，也不替代 worktree、分支与 stash 的发布范围盘点。

脚本测试：`node --test scripts/release-changelog.test.mjs`。测试只操作独立临时目录，不运行构建或修改真实日志。
