# 首个可用未签名 App：0.1.0 发布执行总表

> 本文件是发布执行总表，不是逐代码实施计划。每个子项目开工前，先按 `superpowers:writing-plans` 写可验证的 TDD 计划，再按 `superpowers:subagent-driven-development` 执行、评审与验证。各批只精确提交自己已验证的改动，记录提交号。

## 1. 授权与完成定义

用户已授权持续开发直至发布首个可用 App，暂不做发行者签名。目标版本为 **0.1.0**，范围为 **M0 整改完成 + M1 本地闭环 + macOS 双架构安装包与技能包发布**。

- 继续执行已批准的 M0 整改 D0–D6；本总表不重复裁决，也不改变其技术结论。
- M0 总表中的“不扩展 M1”是当时整改批次的边界；本次新授权允许整改完成后继续 M1。
- 不为常规实现、可逆验证或已授权的发布再次请求笼统确认。
- 不提前要求用户批准尚未实现的产物；真实人工验收留到可运行 App 就绪时，提供具体入口和预期结果。
- 运行单元测试、调用 App HTTP 端点或 UI 自动化，不等于真人批准与真人验收。
- 发布完成必须有冻结 tag、实际安装包、技能包、校验和及发布后回读证据；仅任务打勾或本地版本号不足以完成。

首版让用户从已有 Git 仓库启动：扫描并审阅草稿，批准 B0，在自开的 Claude Code/Codex 会话中领取任务，通过证据验证后合并，在 App 查看态势、回答提问、处理禁止/门禁失败与批准提案。

## 2. 范围和不变量

首版覆盖规格第 18 节 M1 的全部关键闭环。不得以只读 Tauri 画布壳、固定演示数据或模拟完成事件替代。

- 活跃状态由唯一 hub 定序；慢层与快照仅由主干租约持有者经统一写入模块提交。
- 慢层批准绑定对象 ID、内容 hash、目标基线号，提交前再次核对；CLI 没有批准命令或 `human:` 事件入口。
- 证据由共用验证器生成、绑定 tree；Agent 自述完成不转换为已合并。
- 未响应的评审不自动通过，提问不自动猜测继续；硬门禁不增加跳过开关。
- 派生草稿、缓存和索引提供重建路径；用户工作树、index 与全局 Git/harness 配置保持受保护。
- 本地单机不要求云服务、API 账号或 Tower.md 无头启动 harness；费用未知保持 `null`。
- App 关闭窗口不停止已有执行；快层只改变状态编码，不改变节点位置。

本次不扩展 M2/M3：Cloudflare hub、完整多机离线发件箱（保留 R4 已批准的恢复发件箱输入）、多机实测、import/Louvain、一句话生长、生长信号、答案存为决策、临时规则、布局动画、G1/G4/G6 完整门禁均留 M2；无头调度、总控、串行集成队列、MCP 授权路由、运行中注入、四家适配器、技能锁定、地图回放、透镜与 pin 留 M3。

人类密码学签名、配对、认证、加密、钥匙串和无凭据沙箱沿现有规格留安全加固。“暂不签名”不取消产品中的人工放行。

- [ ] 按 M0 整改总表及已写批次计划完成 D0 与 R1–R16；未完成项继续明确标注，不以文档同步替代实现。

- [ ] 用真实 Note.md 仓库验证冷启动覆盖率、每层模块数诊断、验证命令/无测试候选、草稿对象引用与绑定 tree 的初始证据。
- [ ] 在真实 daemon 路径证明私有快照、重建、失效租约、连续水位、断网读取/续租和有界存储；保留既定整改验收。
- [ ] 将各批已验证提交号、剩余限制与 README/双语未发布日志对齐，作为 M1 稳定基线。

M0 的恢复确认端点验收仍按已批准 D2 执行；真人从 App 点击属于 P6/P7，不倒灌为 M0 已完成证据。

## 5. P2：任务门禁与证据链

- [ ] 实现 G0/G2/G3/G5 与 `towermd check`、后台 `finish`、有界 `finish --wait`、`trailers`。
- [ ] 守卫先于验证；未提交改动、慢层改动、越界路径与不基于最新 main 的提交均拒绝，并生成对应中断。
- [ ] finish 复用 P1 验证器，在分离工作树运行所属模块全部验证命令，署名 `process:towermd-verifier`，证据绑定 tree。
- [ ] 验证期间 daemon 续租；验证失败回到运行中，累计失败升级中断；通过后超过 60 分钟未合并释放租约。
- [ ] main 上的任务 trailer 必须对应有效证据；仅 SHA 改写、压缩检查点或允许的快照/画布差异不误使证据失效。

验收同时覆盖通过与拒绝路径、过期 epoch、失败日志、并发验证及 main 变化。没有证据的“done”不能增加进度；伪造 trailer 或不匹配 tree 不能完成任务。

P2 开工时按已有规范同步以下接口澄清，不新增放行例外：

- 空 `Module.verify` 只能产生 `no_tests` 并阻塞 G3；补测试候选先在 S7 或后续 App 提案中批准 L1 的验证命令，再按同一 G3 执行。不能从任务分支发现命令替代权威配置，也不能让空集合默认通过（第 8 节 S7/8.2）。
- `risk: high` 缺有效 G1/G4 人工评审事实时硬阻塞；“完整门禁留 M2”不豁免 FR-58。P3 只需补必要的 review Hold/App 确认，不提前做完整自动评审。
- 合并 deadline 按 FR-112 固定为进入验证中时刻加 60 分钟；通过、轮询、重启、amend 或纯快照变基均不重置。状态表“已通过”描述释放情形，不另起计时。
- FR-99 已要求合并 trailer 携 epoch，FR-12 示例须补 `Towermd-Epoch`（主模块 fence 的 epoch，完整 fences 仍绑定 Evidence/Run）。Task 与 Snapshot trailer 的解析区分上下文；合法 Task+Evidence+Epoch 不能误判坏快照，孤立 Epoch 仍诊断。正常观察、恢复与 outbox 都复用批 3 的同一 Git/Evidence 证明校验器。

以上边界已对照知识库旧规格的 S7、FR-58 核实；不以实现便利降低已有硬门禁。

## 6. P3：提问与人工干预

- [ ] 实现 ask/open/wait/deferred、已有决策引用与归一化问题去重，规则采用规格 FR-59/62。
- [ ] App 本次回答写 hub 并归档；CLI 转述按 FR-96 保留转述属性，不能写成人的决策、规则或批准。
- [ ] 插话与已到回答在下一次任意 CLI 调用输出最前面送达，并写投递事件；检查点调用 status。
- [ ] 暂停全部拒绝新领取，给既有运行送暂停插话；扩大影响面的恢复请求须经 App 确认。
- [ ] 中断保留该任务租约但不阻塞其他模块；等待超时只升级/返回 deferred，不自动继续。

验收通过真实 CLI→daemon→App→CLI 链路。回答保存为决策/临时规则等 M2 选项不得伪装成首版可用按钮。

## 7. P4：草稿、提案与基线放行

- [ ] `baseline submit` 校验统一 schema；S6 由用户现有 harness 会话按技能综合，不引入无头模型调用。
- [ ] S7 提供草稿模块合并、拆分、改名、拖动、接口补充、验证命令确认和已有文档引用。
- [ ] S8 前不写权威慢层；App 显示待批准内容、差异、目标基线和 hash，再发批准事件。
- [ ] 主干租约持有者核对批准内容，在一个提交中写慢层对象、决策、基线清单与 tower.canvas，然后生成 `towermd/B0` 或后续标签。
- [ ] `propose` 包含理由、影响路径/模块/接口/任务、备选与建议；新基线冲突任务标“需复核”。

验收覆盖拒绝、内容被替换、基线已变化、租约失效、提交/标签失败和重试，不允许未批准草稿进入 main。不改变 M0 对用户工作树和 index 的保护；基线写入场景在本批计划中明确验证。

## 8. P5：main 事后检测

- [ ] 每次 fetch 检查 main 新提交；受保护路径变更必须有对应批准/基线/快照事件追溯。
- [ ] 未批准改动生成确定性 eid 的禁止中断，重复检测不重复计数。
- [ ] 卡片提供生成撤销提交、转提案；人自行编辑并推送的慢层改动可经 App 认领。
- [ ] 显示违规提交及 diff，保留原始记录，不将违规变化静默视为已批准基线。

验收故意跳过 finish 的提交，同时证明正常快照、批准基线和合法任务提交不会误报。不得以此声称 v0.1 有无法绕过的合并前集成器。

## 9. P6：可安装 Tauri App

- [ ] 建立项目打开/初始化入口与随包 CLI；App 通过 daemon 读写，识别唯一实例，错误具有可操作诊断。

- [ ] UI 首屏最多 3 项；快层不移动节点；共享样式唯一来源；中断同时使用形状、颜色与文字。
- [ ] 实机验证样式、WebView、启动路径、关闭窗口后 daemon 持续运行、重开恢复以及断连重连。

验收从实际打包 App 启动，不依赖 Vite 或源码目录。Finder 启动时工具链 PATH 与内置 CLI 定位须实际验证；无需用户安装 Node、pnpm、Rust。目标仓库验证所需工具缺失时如实诊断。

## 10. P7：技能交付与真实验收

- [ ] 交付 init、baseline、claim、ask、propose、finish 的 harness 原生技能目录及明确安装步骤，不改全局配置。
- [ ] 技能只经 CLI 写状态，先建工作树/分支再领取；长操作和检查点续租；finish 在其他技能合并步骤之前。
- [ ] seed 属 M2，首版说明其未交付，不能附带调用不存在命令的可执行技能。
- [ ] 在可运行 App 就绪后提供具体真人恢复确认入口，记录真人操作后的恢复结果；UI 自动化只作为补充回归证据。
- [ ] 本机 3 个工作树用 Claude Code 与 Codex 的真实会话完成 10 个任务，逐项记录运行、harness 版本、tree、验证证据、main trailer 与合并后验证。
- [ ] 验证无证据完成不计进度、越界/慢层拦截或事后检测、trailer/压缩后识别，以及 CLI 无批准/`human:` 入口。

先运行自动集成测试覆盖机制，再积累真实技能使用证据；10 次模拟 CLI 或 fixture 不替代双 harness 十任务。复用用户已有 harness 会话和账号，不要求新 API 账号或以无头调度凑验收。

## 12. 依赖与当前环境

具体依赖沿 Note.md 同版本线：pnpm 11.7.0、Tauri 2、Svelte 5、TypeScript 5、Vite 6、Svelte Flow 1.6.6、vitest 4、svelte-check 4；渲染库和测试库按实际使用引入。NFKC 可沿用 Note.md 的 `unicode-normalization 0.1`。

新增依赖先核 Note.md；不为尚未实现的功能预装库。elkjs 属 AGENTS.md 已选类别，若确需，先在对应计划论证用途、版本与只在冷启动/新基线布局的边界，不默认带入其他布局库。M2 WebSocket 客户端、签名和钥匙串库不在本次引入。

只读检查时：cargo 可经 `~/.cargo/bin/cargo` 使用但不在当前 PATH，仅装 aarch64 target；Xcode/SDK、Node 与两种 harness CLI 可用；全局 pnpm 为 10.34.5、corepack 缺失。项目工具版本需显式固定，不修改全局配置；Intel target 与构建依赖在构建子计划中处理。

当前发布通道**未验证**：`git ls-remote` 因 github.com DNS 解析失败，`gh auth status` 报默认 token 无效。这不证明 SSH 推送权限本身不存在；先完成不依赖发布网络的开发和本地构建，临近发布再核最小通道。不读取秘密、不自动换账号、不把未发布本地产物称为公开发布。
